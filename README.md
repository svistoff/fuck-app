# Знакомства — локальный сайт знакомств для одного города

Серверный рендеринг (Node + Express + SQLite), без SPA — ради SEO и простоты эксплуатации.
Один процесс Node, база в файле, фото на диске VPS.

## Что умеет

- **Главная и каталог открыты всем** (без входа) — с фото и кликабельными контактами. Это нужно для индексации в поиске.
- **Регистрация/вход по email (magic link)** — без пароля. Ссылка действует 30 минут. Регистрация — это размещение анкеты (для девушек); мужчинам регистрация не нужна, они просто смотрят. Поля «пол» нет.
- **Анкета**: имя, возраст, район (выбор из списка районов города), рост, вес, грудь, галочка «выезд», краткое и полное описание, до 4 фото, контакты. Параметры видны на карточке под описанием и блоком на странице анкеты.
- **Главное фото**: после загрузки можно выбрать, какое фото сделать основным (кнопка ★).
- **Контакты 5 типов** с официальными иконками: телефон (звонок), WhatsApp (по номеру), Telegram / MAX / Instagram (по username).
- **Фото**: при загрузке автоматически сжимаются и **очищаются от EXIF (включая GPS-координаты)** — требуется пакет `sharp` (см. ниже). На странице анкеты фото показываются **каруселью** (без обрезки), листание свайпом/стрелками.
- **Реклама в ленте**: баннеры (картинка + ссылка) вставляются в каталог после каждых 10 анкет; если баннеров несколько — чередуются по кругу. Управление в админке → «Баннеры».
- **Встраиваемый виджет** для других сайтов: `<iframe src="https://ВАШ-ДОМЕН/embed?count=5&ref=site2" width="100%" height="320" frameborder="0"></iframe>`. Показывает N анкет из общей базы (ротация та же) и кнопку «Перейти на сайт». Параметр `ref` помогает отследить, с какого сайта пришли.
- **Ротация**: каждые 15 минут верхняя анкета уходит вниз, по кругу. Порядок считается от времени — без фоновых задач.
- **Админка** (отдельный вход логин+пароль): статистика, создание анкет **вручную**, редактирование/скрытие/удаление анкет и фото, закрепление наверху, баннеры, SEO-страницы, логотип/фавикон, мета-данные и код аналитики.
- **SEO**: серверный HTML с title/H1/description/keywords, `robots.txt`, `sitemap.xml`, JSON-LD (Person) и og:image на анкетах, посадочные страницы под низкочастотные запросы — поштучно или **массовой загрузкой готовых .html-файлов**.
- **Брендинг**: логотип и фавикон загружаются из админки (вместо текста), настраивается «город в предложном падеже» (чтобы было «Знакомства в Казани», а не «в Казань»).
- **Защита**: лимит запросов magic-ссылок (5 за 15 минут с IP) + honeypot-поле против спам-ботов.
- **Защита**: лимит запросов magic-ссылок (5 за 15 минут с IP) + honeypot-поле против спам-ботов; **блокировка одноразовых почтовых ящиков** (список в `src/disposable.js`); блокировка аккаунта админом с экраном «Подать апелляцию» (апелляции читаются в Админка → «Апелляции»). Блок аккаунта также помечает его устройство (мягкий сигнал, обходится сменой браузера).
- **Лента**: каталог подгружается бесконечной прокруткой (первая порция — серверным HTML для индексации, дальше автоматически).
- **18+**: оверлей-подтверждение возраста (контент остаётся в HTML и индексируется).

## Обновление существующей базы (миграция round-3 → round-4)

Если анкеты уже созданы — **базу не удалять**. Новые поля добавляются миграцией без потери данных:

```bash
cd /var/www/fuck-app
cp data/app.db /root/app.db.bak           # бэкап
sqlite3 data/app.db < migrate-v4.sql       # добавит колонки (выполнить один раз)
# перезапуск (новые таблицы appeals/blocked_devices создадутся сами при старте)
supervisorctl restart gorod-dating
```

Старые анкеты сохранятся, новые поля (рост/вес/грудь/выезд) у них будут пустыми — дозаполнишь вручную. Не забудь в Админка → «Настройки» указать «город в предложном падеже» = **Екатеринбурге**.

## Требования

- Node.js 18+ (рекомендуется LTS — 20 или 22 LTS; для них есть готовые бинарники `better-sqlite3`).
- VPS с nginx (раздаёт HTTPS и статику) и доменом.
- Аккаунт [Resend](https://resend.com) с верифицированным доменом (для писем).

## Установка на VPS

```bash
git clone <repo> /var/www/example.ru
cd /var/www/example.ru
npm install --omit=dev
cp .env.example .env
```

Заполни `.env`. Сгенерируй секреты:

```bash
# SESSION_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# ADMIN_PASS_HASH (подставь свой пароль)
node -e "console.log(require('./src/auth').hashPassword('ТВОЙ_ПАРОЛЬ'))"
```

Скопируй полученные значения в `.env` (`SESSION_SECRET` и `ADMIN_PASS_HASH`).
Укажи `BASE_URL` (свой домен, без слэша в конце), `CITY_NAME`, `MAIL_FROM`, `RESEND_API_KEY`,
и `UPLOAD_DIR` (абсолютный путь, напр. `/var/www/example.ru/uploads`).

## Почта (Resend)

1. Заведи домен в Resend → добавь предложенные DNS-записи (SPF, DKIM, при желании DMARC).
2. Дождись статуса «Verified».
3. `MAIL_FROM` должен быть на этом домене, напр. `Знакомства <noreply@example.ru>`.
4. Без верификации письма уходят в спам. Бесплатного тарифа (3000 писем/мес) хватает для входов.

На время локальной отладки поставь `MAIL_DEV_LOG=1` — ссылка будет печататься в консоль, письмо не отправляется.

## Запуск

```bash
# напрямую
npm start

# через pm2 (рекомендуется)
npm i -g pm2
pm2 start ecosystem.config.js
pm2 save && pm2 startup
```

## Nginx

Смотри `nginx.example.conf`. Главное:
- HTTPS-сертификат (Let's Encrypt / certbot);
- `location /uploads/` отдаёт фото напрямую с диска (`alias` на твой `UPLOAD_DIR`);
- всё остальное проксируется на `127.0.0.1:8080`;
- `client_max_body_size 12m;` под загрузку фото.

## Админка

`https://example.ru/admin/login` — логин из `ADMIN_USER`, пароль тот, для которого сгенерирован `ADMIN_PASS_HASH`.

### SEO-страницы под ключевые слова

Админка → «SEO-страницы». Два способа:

1. **Поштучно** — «Новая страница»: URL (slug, латиница/цифры/дефисы), Title / H1 / Meta description / Ключевые слова, текст (HTML).
2. **Массово** — блок «Массовая загрузка»: выбираешь сразу несколько готовых `.html`-файлов. Имя файла станет адресом (`centre.html` → `/centre`), а Title / Meta description / H1 возьмутся из тегов внутри файла, текст — из `<body>`.

Страницы сразу попадают в `sitemap.xml` и индексируются как обычные.

> ⚠️ **Важно про массовые страницы.** Десятки почти одинаковых страниц «под ключевики» Google и Яндекс считают *дорвеями* и могут понизить весь сайт. Чтобы это работало в плюс, страницы должны быть реально разными и полезными (уникальный текст, смысл), а не клонами с подменой слова.

Мета-данные и вступительный текст главной, **город в предложном падеже**, логотип/фавикон и **код аналитики** (Яндекс.Метрика/Plausible — вставляется перед `</body>`) правятся в Админка → «Настройки».

## Обработка фото (sharp)

Пакет `sharp` (в зависимостях) при загрузке ужимает фото до 1600px и **вырезает метаданные EXIF, включая GPS-координаты съёмки** — это важно для безопасности девушек. У `sharp` есть готовые бинарники под LTS-версии Node, отдельно ничего собирать не нужно — просто `npm install`. Если `sharp` почему-то не установился, сайт продолжит работать, но фото будут сохраняться **как есть** (без сжатия и без удаления EXIF) — в логе появится предупреждение.

## Бэкап

Вся база — один файл `data/app.db`, плюс папка с фото (`UPLOAD_DIR`). Простой ежедневный бэкап:

```bash
# crontab -e
0 4 * * * sqlite3 /путь/data/app.db ".backup '/backup/app-$(date +\%F).db'" && tar czf /backup/uploads-$(date +\%F).tgz -C /путь uploads
```

## Что пока упрощено (можно добавить позже)

- **18+**: это подтверждение (галочка-оверлей), а не проверка по документам.
- **Жалобы и блокировки**: добавляются отдельно при необходимости.
- **Локация**: текстовое поле «район/улица», без карты.
- **MAX**: ссылка ведёт на профиль по username (`max.ru/username`) — у MAX нет публичной ссылки «диалог по номеру».

## Контент-завод и блог (SEO-пристройка)

К сайту присоединён контент-завод и блог — ради органики и ссылочной массы.

- **Блог** живёт в этом же Node-процессе (`src/blog.js`): страницы `/blog` и
  `/blog/<slug>` (можно вынести на поддомен, см. `BLOG_HOST`/`BLOG_BASE_URL`).
  Серверный HTML, schema.org (Article+FAQPage), статьи в общем `sitemap.xml`,
  в каждой статье ссылки на каталог анкет.
- **Контент-завод** — отдельный Python-сервис в `content-radar/` (FastAPI),
  размещается на `content.<домен>`, закрыт логином/паролем. Находит видео на
  YouTube, по ним ИИ готовит статьи; кнопкой «Опубликовать в блог» статья
  улетает в блог через внутренний API `POST /internal/blog/publish`
  (Bearer `BLOG_INGEST_TOKEN`).

Переменные блога — в `.env` (см. `.env.example`, блок «Блог»). Завод
настраивается в `content-radar/.env` (см. `content-radar/README.md`). nginx на
поддомены — `deploy/nginx.conf`. Оба сервиса под pm2 — `ecosystem.config.js`.
